Zero to a validated spec in under ten minutes

Quick start

Five steps: install the harness once, define your first spec through a guided interview, validate and critique it, visualize the hierarchy, and preview a release — all in plain language, no code required from you.

STEP 1

Install once

One command drops the coordinated .claude/ rig — four skills, seven critique sub-agents, hooks, rules, and the shared eval-gate — into your project. Requires Python 3.11+. Full details and options on the Install page.

POSIX (macOS / Linux / WSL)

bash .claude/skills/product-spec/install.sh

Windows (PowerShell)

powershell -ExecutionPolicy Bypass -File .\.claude\skills\product-spec\install.ps1

The installer creates the shared venv at .claude/skills/.venv/, installs pyyaml, and vendors Mermaid, marked, and DOMPurify for offline HTML output — verifying each against a pinned SHA-256. Re-running is safe (idempotent). After install, open Claude Code in your project folder so it picks up the new skills, then proceed below.

STEP 2

Define your first spec

Run product-spec from the Claude Code command palette. With no flags it shows a menu; the interview walks you through Vision → BRD → PRD → Epic → Story with acceptance criteria, one question at a time. Output lands in docs/product/ — markdown files with YAML frontmatter, never written elsewhere. See the product-spec skill page and spec hierarchy for the full contract.

STEP 3

Validate & critique

--validate runs deterministic scripts first (orphans, missing AC, ID integrity, broken trace) then an LLM judgment layer (INVEST, vagueness, core-value drift). It is the reproducible gate. product-spec-critique goes further — four lens sub-agents tear the same spec apart and say what --validate cannot: why it would die in the market. FAQ

Common questions

Do I need to write any code?
No. The four skills are invoked entirely through the Claude Code command palette in plain language. The product-spec and product-spec-critique skills are designed specifically for non-technical product owners.
Where does the spec output land?
product-spec writes only to docs/product/ inside your project — markdown files with YAML frontmatter. It never writes prose anywhere else in the repo.
Can I re-run the installer safely?
Yes — the installer is idempotent. Each step checks whether it is already done and skips if so. The vendored JS files are verified against pinned SHA-256 hashes on every run.
Can I use the harness in Vietnamese?
Yes. Pass --lang vi and the interview, story descriptions, and AC are written in Vietnamese. IDs and frontmatter keys stay English for structural stability. Visualization labels also localize. The telemetry skill narrates entirely in plain Vietnamese by default.
What if the HTML visualization shows a blank diagram?
Re-run the installer — it will re-vendor the Mermaid engine. ASCII and body views never require the CDN; only Mermaid graph views fall back to a CDN script if the local vendor copy is missing.
What happens if a new claim contradicts an approved artifact?
The harness surfaces the contradiction verbatim and gives the PO three choices: Keep (reject the new claim), Change (re-approve with owner + date), or Hybrid (record both, schedule a follow-up). It never silently picks a side or edits approved content.
