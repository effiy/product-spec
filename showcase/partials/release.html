For developers

release

v1.2.0

Two halves of one job: pack a curated .claude/ subset into a deterministic tar.gz, and run the release lifecycle on the root CHANGELOG.md. Same inputs → byte-identical bundle, every time.

✓ Reach for it when

  • sharing/installing a curated .claude/ subset
  • cutting a versioned release (lock changelog, bump, tag)
  • you need a reproducible, hashed artifact

✗ Won't do

  • pack secrets — the safety filter is non-removable
  • push the tag for you — that's owner-owned
  • make any network call at runtime

The safety filter, doing its job

Plant secrets in a tree, then scan it. Legit files stay; secrets are dropped by an immutable rule — no flag pulls them back. real scan

Always-dropped: .env & secrets/keys, .git/, runtime caches, session state, telemetry/*.jsonl, tests. Settings & CK-config are opt-in only.

Release lifecycle (release.py)

Lock [Unreleased] → [X.Y.Z], bump the manifest, hand the owner the tag push. The tag — never auto-pushed — fires the CI that publishes the GitHub Release.

--extract--release X.Y.Z--bump major|minor|patch--pre-release--date--apply--push
