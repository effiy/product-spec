Under the hood — the full .claude/ anatomy

The Rig

/skills · /agents · /hooks · /rules · /_shared

The homepage teaser names the pieces. This page walks each one. Installing the bundle drops a single coordinated .claude/ tree into your project — four skills, seven critique sub-agents, hooks that instrument them, rules that steer the orchestration, a shared eval-gate, and a deterministic packager. All wired to work together; nothing requires a server or a network call at runtime.

The full install map

What installs — the coordinated .claude/ tree

A single install.sh (or install.ps1) call places all six groups of components under your project's .claude/ directory and creates the shared Python virtual environment. The table below is the exact layout — no generated runtime files, no hidden extras.

Component Path Count What it is
Skills .claude/skills/ 4 User-invocable /cleanmatic:* commands. Each is self-contained with its own scripts/, references/, and guides.
Sub-agents .claude/agents/ 7 Critique lens critics + consolidator + humanizer + memory harvester — spawned by product-spec-critique and --reflect.
Hooks .claude/hooks/ 7 5 telemetry sinks (auto-registered) + memory-gap enforcement + critique-nudge (both opt-in).
Rules .claude/rules/ 5 Workflow · orchestration · development · documentation rules + the always-on safety floor (CLAUDE.md).
Shared eval-gate .claude/skills/_shared/lib/ 2 scripts run_evals.py (structural) + llm_eval.py (advisory) + runnable golden fixtures bundled per skill.
Packager + installer project root — pack.manifest.yaml + install.sh / install.ps1 — deterministic builder and multiplatform installer that recreates the shared venv.

Generated at runtime (not bundled): your spec under docs/product/, telemetry sinks under .claude/telemetry/*.jsonl (gitignored), and reproducible tarballs under dist/.

Component by component

The pieces — a closer look

4 skills/skills
  • product-spec — interview, spec, validate, viz
  • product-spec-critique — 4-lens tear-down, 9 voice levels
  • release — pack into deterministic tar.gz
  • telemetry — read-only usage & health, 8 lenses

All four share one Python venv at .claude/skills/.venv/. Telemetry's lenses and sink hooks are stdlib-only and also run under a plain system python3.

7 sub-agents/agents
  • product-critic — JTBD · Value Prop · Kano · RICE
  • tech-critic — INVEST · testability · NFR gaps
  • market-critic — Lean Canvas · Porter · Blue Ocean
  • craft-critic — writing quality, CSI-4Cs, term drift
  • critique-consolidator — merges 4 lenses, deduplicates, top-3
  • critique-humanizer — strips AI-tells, preserves bite
  • memory-harvester — retroactive harvest for --reflect

Sub-agents are spawned by the skills — they are never user-invocable directly. They read, never write.

Hooks/hooks
  • 5 telemetry sinks (auto-registered at install)
    • track_skill_invocation.py — skill invocation events
    • track_script_execution.py — script duration + exit code
    • track_subagent_outcome.py — sub-agent success / failure
    • mark_bash_start.py — bash command timing
    • emit_session_summary.py — session summary on close
  • memory_gap_hook.py — memory-gap enforcement (opt-in)
  • product_spec_critique_nudge.py — post-validate re-critique reminder (opt-in)

Sinks are fail-open and make no network calls. They write only to gitignored .claude/telemetry/*.jsonl sinks. Opt out with register_telemetry_hooks.py --remove.

Rules/rules
  • CLAUDE.md — always-on safety floor + skill routing table
  • primary-workflow.md — understand → implement → verify → explain
  • orchestration-protocol.md — delegation context + parallel work rules
  • development-rules.md — YAGNI / KISS / DRY, quality gates, tooling
  • documentation-management.md — when to update docs, plan location conventions

The two GATEs in CLAUDE.md (GATE-NO-SILENT-REVERSAL and GATE-NEVER-ASSUME) apply on every turn regardless of which skill is active. They cannot be deferred to a loaded reference.

Shared eval-gate/_shared
  • run_evals.py — structural checks; runs on CI; deterministic
  • llm_eval.py — advisory LLM-backed checks; never in CI gate
  • Each skill ships its own eval/golden/ fixtures — runnable on your machine via the shared eval scripts.

The script-vs-LLM split is an operating principle: scripts handle graph and structure; the LLM layer judges prose and alignment. Scripts always run first. See the five principles.

Packager + installerroot
  • pack.manifest.yaml — source-of-truth manifest; curated file list + per-file SHA-256
  • install.sh — POSIX installer (macOS / Linux / WSL); idempotent
  • install.ps1 — Windows PowerShell installer; same behavior
  • Output: dist/product-spec-{version}.tar.gz + .sha256 sidecar. Byte-identical across runs given the same inputs.

The release skill manages the pack lifecycle. See release for flags, dry-run preview, and CI reproducibility. See telemetry for usage & health of the whole rig.

No network calls at runtime

Runs offline — by design

After install, all four skills run entirely on your machine. The telemetry sink hooks and lenses are stdlib-only — they read and write only local gitignored .claude/telemetry/*.jsonl sinks and never transmit anything. The release safety filter always drops .env files, secrets, keys, .git/, runtime caches, and session state from any bundle — no flag can override this.

One-time install: CDN fetch + SHA-256 verify

The product-spec installer downloads the Mermaid, marked, and DOMPurify runtimes from the public CDN (cdn.jsdelivr.net), then verifies each against a pinned SHA-256 hash before storing them locally. After that step, the viz engine runs offline.

Degraded-install caveat: Mermaid graph views

If mermaid.min.js failed to vendor at install time, product-spec's Mermaid graph views fall back to a CDN <script> at browser-render time. Re-run the installer to fix it. ASCII and body views never reach a CDN.

Idempotent re-install is always safe

Both install.sh and install.ps1 are idempotent — re-running them skips already-present components and re-vendors any missing JS assets. No state is lost.

🔒
Privacy guarantee: all four skills make no network calls at runtime. Telemetry data stays local in gitignored .claude/telemetry/*.jsonl files — it is never bundled or transmitted. The release safety filter permanently excludes secrets, .env, .git/, and session state from every bundle. These protections have no opt-out flags.
