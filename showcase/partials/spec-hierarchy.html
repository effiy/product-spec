The backbone of every spec — Vision to Story

Spec Hierarchy

5 levels · parent-scoped IDs

Every spec is a single directed tree: one Vision anchors one BRD which spawns many PRDs, each PRD owns Epics, each Epic owns Stories. IDs encode lineage — a script can resolve any Story all the way up to its BRD goal without reading prose. Frontmatter is always the source of truth; the LLM never infers structure from headings.

THE FIVE LEVELS

Vision → BRD → PRD → Epic → Story

Each level has a single, non-overlapping job. A product owner authors each node in conversation with the skill; the skill never invents scope or personas.

VISION North-star + personas One narrative statement of what the product is, who it serves, and what core value it delivers. Home for persona labels that all downstream nodes inherit. One per product.
BRD Business goals + success metrics A single Business Requirements Document that lists measurable goals (BRD-G1, BRD-G2, …). Each goal carries ≥1 metric slug. PRDs must link back to at least one BRD goal. One per product.
PRD Feature-area scope + requirements One Product Requirements Document per feature area (e.g. PRD-AUTH, PRD-CATALOG). Declares scope, moscow, personas, and links to its BRD goals. Many PRDs per BRD.
EPIC A deliverable slice of a PRD A coherent chunk of work that delivers standalone value. Owns a target_date, horizon, and optional risks. ID is parent-scoped: PRD-AUTH-E1, PRD-AUTH-E2. Many epics per PRD.
STORY Atomic unit with acceptance criteria The build team's direct input. Must carry ≥1 acceptance criterion in Given-When-Then form. ID is parent-scoped: PRD-AUTH-E1-S1. Many stories per epic.

HOW IDS ARE FORMED

Parent-scoped, lineage-readable, no central allocator

Every ID encodes its full ancestry. A script that reads PRD-AUTH-E1-S1 knows the story belongs to epic E1, which belongs to PRD-AUTH, which belongs to the BRD — without opening a single file.

Artifact Pattern Example Slug rules
BRD goal BRD-G<n> BRD-G1, BRD-G2 Next free integer in BRD
PRD PRD-<SLUG> PRD-AUTH, PRD-BILLING Uppercase, ≤16 chars; regex ^[A-Z][A-Z0-9-]{0,15}$
Epic PRD-<SLUG>-E<n> PRD-AUTH-E1, PRD-AUTH-E2 Next free integer within that PRD
Story PRD-<SLUG>-E<n>-S<n> PRD-AUTH-E1-S1 Next free integer within that epic
Decision DEC-<n> DEC-1, DEC-2 Globally monotonic; never reused
Outcome OUT-<n> OUT-1, OUT-2 Globally monotonic; never reused
📌
The slug is permanent. Renaming a PRD does not update existing epic/story IDs — they keep the original lineage. IDs and frontmatter keys always stay English even when the content language is Vietnamese.
FRONTMATTER IS SOURCE OF TRUTH

Parse YAML — never infer structure from headings

This is Operating Principle 1. Every artifact carries a YAML frontmatter block at the top of the file. Scripts parse it exclusively. The prose body below the frontmatter is for human readers only — the skill never reads headings to decide what type of artifact something is or what its status is.

Universal frontmatter fields

id type status draft|review|approved lang en|vi owner created updated version

Parent-link fields

story → epic: PRD-AUTH-E1 epic → prd: PRD-AUTH prd → brd_goals: [BRD-G1]

A missing referent is a dangling_link error at validate time.

Anti-rationalization: "The heading says APPROVED" is not evidence. Only status: approved in frontmatter counts. "The file tree shows graph state" is not evidence. Run the scripts first.
SCOPE & CORE VALUE

Every node declares its scope — PO decides, never the skill

Scope is the PO's call. The skill surfaces the question during the interview and records the answer in frontmatter. It never assumes or defaults a scope. The three values are:

Value Meaning LLM check
in In scope for the current release Core-value alignment scored: aligned / weak / off
out Explicitly out of scope; excluded from most views —
core-value PO's claim: this is part of the stated core value proposition Highest alignment bar; competitive-drift check applies when ≥2 competitors tracked
⚖️
GATE-NEVER-ASSUME: the skill never sets scope: core-value on the PO's behalf. It also never defaults scope when the PO is ambiguous — it asks. Scope is PO's call, non-negotiable.
