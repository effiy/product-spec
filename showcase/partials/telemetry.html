telemetry

v1.1.0

After you've used the harness a while, telemetry tells you — in plain Vietnamese — how your own tooling is doing. A script gathers deterministic counts; the skill narrates them. It reports whether the machinery runs (usage & health), never whether the product wins the market.

✓ Reach for it when

  • you want to know which skills actually get used
  • a script is erroring or slow and you want proof
  • checking subagent success / validate-pass health

✗ Can't tell you

  • market or user outcome — usage ≠ effectiveness
  • exact tokens/ms — those are labelled "ước lượng"
  • what to prune — it suggests, never edits
Worked example

One lens, four formats

The usage lens over the same data, rendered four ways: ascii to glance, md to paste, mermaid to chart, json to pipe. sample data

analyze_telemetry.py --lens usage --format ascii --lang vi

Mermaid is shown as source — the page vendors no chart library, staying dependency-free. Numbers are clearly-labelled sample data.

Every report ends with what it does not measure:

  • market / user outcome — usage ≠ effectiveness
  • any thin lens → "chưa đủ dữ liệu", never spun
  • suggestions only — no authority to prune or edit
🪝
5 telemetry sink hooks + 2 enforcement hooks share one runtime and one on/off file. The 5 sinks auto-register at install, are fail-open, make no network calls, and write only to gitignored .claude/telemetry/*.jsonl. The 2 enforcement hooks (memory-gap, critique-nudge) default off — a blocking hook is never fallback-enabled. Global kill-switch: CK_TELEMETRY_DISABLED=1.
