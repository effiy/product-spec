scan & go

Every flag of all four skills, organised by skill. The most-used flags sit in the visible table; the long tail collapses into a disclosure block. Every flag here is verified against its SKILL.md — nothing invented. Need to pick a skill first? Use the skill finder.

Install

Each skill ships its own installer. All four share one Python venv at .claude/skills/.venv/. Requires Python 3.11+.

POSIX (macOS / Linux / WSL)
bash .claude/skills/product-spec/install.sh
Windows (PowerShell)
powershell -ExecutionPolicy Bypass -File .\.claude\skills\product-spec\install.ps1

Replace product-spec with release, product-spec-critique, or telemetry for those skills. Any installer bootstraps the shared venv — re-running is safe (idempotent).

product-spec flags

Invoke with /cleanmatic:product-spec [--flag] [target]. Full guide: product-spec skill page.

FlagWhat it does
(no flag)Detect state → present menu (init / BRD / PRD / stories / validate / update / viz / approve / summary).
--productInit or refresh PRODUCT.md (thin product-context labels).
--brdCreate or refine the single BRD (business goals + metrics + stakeholders).
--prd [feature]Create or refine a PRD for a feature area. Multiple PRDs supported.
--epic [prd]Create or refine an epic under the given PRD.
--story [epic]Create or refine a story under the given epic.
--autoBrain-dump → decompose into BRD goals / PRDs / epics / stories; confirm-batch on ambiguous splits.
--validateRun structural scripts → layer LLM judgment → human report. Deterministic gate.
--approveValidate → open-questions gate → record owner + date → flip status: approved. Nudges --export and --viz afterward.
--updateDelta-update: ask what changed → flag affected downstream nodes for PO review. Never auto-rewrites prose.
--viz <view>Render a visualization (20 views: graph/body/governance/learning). See skill page for the full matrix.
--summary1-page exec brief. Add --audience release-notes for a delta since last approved.
--statusRead-only health nudge: last-validated errors/warns + open-question markers. Does not re-run validate.

product-spec-critique flags

Invoke with /cleanmatic:product-spec-critique [scope] [--flags]. Full guide: critique skill page.

FlagWhat it does
[scope]Artifact ID to critique (PRD-AUTH, PRD-AUTH-E1, …) or all (default). Full ancestry is always pulled as context.
--productRun only the product lens (JTBD / Value Prop / Kano / RICE / riskiest-assumption).
--techRun only the tech lens (INVEST / testability / hidden dependencies / NFR gaps).
--marketRun only the market lens (Lean Canvas / Porter-light / Blue Ocean / unit-economics / JTBD-competition).
--craftRun only the craft lens (clarity / conciseness / consistency / correctness / term drift / vague adjectives).
--interactiveAskUserQuestion to pick scope + lenses + level before running.
--level 1..9Voice intensity. Default = 5 (no-mercy). Aliases 1–6: --warm · --gentle · --blunt · --savage · --no-mercy · --roast. Levels 6–9 carry a danger gate (confirm + AskUserQuestion). Level 9 re-confirms on every run. Universal-harm floor applies at all levels.
--lang vi|enCritique output language. Default vi. IDs and frontmatter keys stay English.
--no-webDisable the market lens's WebSearch/WebFetch. With no competitors: in BRD, flags missing competitive grounding rather than fabricating.
More critique flags — fresh · refresh-web · inherit · rollup · no-inherit · no-rollup
FlagWhat it does
--fresh / --forceBypass ALL reuse: force a full fresh run (provenance.reuse = none), re-running every lens even when nothing changed.
--refresh-webForce the market lens to re-fetch URLs (ignore the 14-day web-cache). --no-web still wins over this.
--no-inheritDisable parent→child inherited context (prior parent blockers surfaced as child risk). Default ON.
--no-rollupDisable child→parent descendant rollup (critiqued children's verdicts aggregated onto parent). Default ON.
--inherit nearest|deepInherit depth: nearest (default) = nearest critiqued ancestor per branch; deep = every critiqued ancestor in the chain. Implies inherit ON.

telemetry flags

Invoke with /cleanmatic:telemetry [--flags]. Read-only — no writes. Full guide: telemetry skill page.

FlagWhat it does
--lens allFull dashboard (usage + session + health + reliability + workflow + validate + memory + product_memory + artifact_heat). Default when no lens specified.
--lens usageInvocation counts, per-skill tokens (approx), never-used catalog entries.
--lens sessionSession count, avg/median duration, files touched, subagents, skill co-occurrence.
--lens healthPer-script runs / errors / error-rate + avg ms (approx).
--lens reliabilitySubagent success / api_error / timeout / blocked / unknown per type.
--lens validateValidate-pass proxy — internal spec quality signal, NOT market outcome.

--format ascii|md|mermaid|jsonOutput format. Default ascii.
--lang vi|enNarration language for fixed labels. Default vi.
