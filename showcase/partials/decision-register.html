Every PO ruling — recorded, never re-litigated

Decision Register

DEC-<n> · --decision

When a contradiction with an approved artifact surfaces — or when the PO makes a call that settles a debate — the ruling is recorded as a DEC-<n> entry in docs/product/decisions.md. This is the authoritative home for ruled drift. Downstream artifacts that changed as a result point back with po_ruling_ref: DEC-<n> so the same ground is never covered twice.

WHEN A CLAIM CONTRADICTS APPROVED

GATE-NO-SILENT-REVERSAL — surface verbatim, never flip

A new claim that contradicts an approved artifact is a stop point. The skill does NOT edit the artifact, pick a side, or tidy up the inconsistency. It surfaces the contradiction verbatim and presents exactly three choices to the PO. This gate is always on — it is never waived, even when the PO says "just proceed".

Two ways a decision gets opened

Auto-opened by contradiction

--validate or --update detects a contradiction with an approved artifact → GATE fires → PO chooses Keep / Change / Hybrid → ruling recorded as DEC-<n>.

PO-direct via --decision

The PO records a ruling they've already made, without a triggering contradiction — e.g. "we settled the guest-checkout debate, log it." Distinct from --reflect, which recovers decisions that were never logged.

What the skill never does

  • Auto-flip an approved artifact based on a contradiction
  • Invent a DEC-<n> without explicit PO confirmation of the ruling text + rationale
  • Re-litigate a decided DEC-<n> on its own initiative
  • Skip the gate when the PO says "skip asking"
KEEP · CHANGE · HYBRID

Three choices — only the PO decides

When GATE-NO-SILENT-REVERSAL fires, the skill presents the contradiction verbatim and waits. Exactly three choices are offered — no defaults, no hints about which one to pick.

Keep Change + re-approve Hybrid
What each choice means
  • Keep — reject the new claim. The approved artifact is unchanged. The new claim is recorded in DEC-<n> as rejected, with rationale.
  • Change — accept the new claim. The PO must supply an owner name and date for re-approval. Only then does the skill update the approved artifact and bump approved_version. This is the only path that touches approved content.
  • Hybrid — record both the existing and new claim; define a follow-up to reconcile. Neither version is auto-discarded. The tension is preserved and documented until the PO resolves it explicitly.
⚠️
If unsure whether it truly contradicts — ask. Surfacing a contradiction that turns out to be a misread is far safer than silently reversing approved content that was intentional. When in doubt, treat it as a contradiction and surface it.
RECORDED SO IT'S NOT RE-LITIGATED

The register is append-only — one writer, no overwrites

All writes go through decision_register.py --append. The file is append-only: prior records are byte-unchanged. Each entry is a ----fenced YAML block plus a ## DEC-<n> heading and a free-text rationale note — the same storage model as the Outcome Register.

Decision Register — decisions.md

Authoritative home for ruled drift. Monotonic DEC-<n> IDs; never reused. Downstream artifacts that changed point back via po_ruling_ref: DEC-<n>. View with --decision list; record with --decision.

Outcome Register — outcomes.md

Sister register written by --learn. Records measured outcomes vs BRD goals as OUT-<n> entries. A miss on an approved goal is surfaced to the PO, never auto-edited — same no-silent-reversal guarantee.

Example DEC-1 entry (illustrative — not captured output):

product-spec --decision list
## DEC-1

---
id: DEC-1
ruling: change
artifact: PRD-CHECKOUT
contradiction: "New claim sets scope: out; existing approved says scope: core-value."
choice: Change
re_approved_by: "Jane Doe"
re_approved_at: "2026-06-17"
re_approved_version: "1.1.0"
rationale: >
  Guest checkout removed from core-value after competitive analysis showed
  no differentiation vs Shopify. Moved to 'next' horizon as scope: in.
---
⚖️ What the register cannot do
  • Prove a ruling was well-reasoned — it records that the PO made it, not that it was correct.
  • Auto-propagate a ruling downstream — the impact-pass flags affected nodes for PO review; regeneration is opt-in.
  • Replace --reflect — if decisions were made but never logged, --reflect recovers them retroactively from git history and .memory/.
