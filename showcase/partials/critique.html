An opinion, not a pass/fail

product-spec-critique

v1.3.0

--validate says the spec is sound. Critique says whether it is any good — a brutal-but-grounded tear-down across four lenses that reuses validate's findings as ammo, then says what validate cannot: why it would die, where it sits in the market, whether the writing holds up. It never edits your spec and is never in a CI gate.

✓ Reach for it when

  • --validate passes but the spec still feels weak
  • you want the why-it-dies + market + craft read
  • before committing real build budget to an epic

✗ Not for

  • a CI gate — it's an opinion, non-deterministic
  • structural checks — that's --validate's job
  • editing the spec — it only reports

⚙️
How a critique is built: critique_scan.py assembles one evidence bundle → four read-only lens agents fan out in parallel → an opus consolidator dedups, ranks, picks the top-3, flags repeat-offenders → a sonnet humanizer strips AI/translation tells while keeping the bite → the main agent writes one markdown report. Re-runs are cheap: unchanged spec reuses cached lens arrays; a bare level bump only re-renders the voice.

The voice dial — what each level means

Drag from gentle to brutal. Default is 5. Levels 1–4 only ever attack the artifact. 6–9 are dangerous, opt-in, and 9 re-confirms on every run.

⛔ Universal-harm floor — at every level, even 9, even with consent. The line is the target, not the harshness: it attacks the work, never you. No real-violence threats, no protected-characteristic slurs, no family-targeted profanity, no self-harm or sexual content. Every line always keeps an evidence ID and a fix.
